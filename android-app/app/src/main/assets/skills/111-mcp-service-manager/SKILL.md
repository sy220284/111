# 安卓 MCP 服务管理

仅在用户明确要求接入、更新、移除、授权或修复 MCP 服务时使用本技能。MCP 设置页是只读的可用服务目录，服务管理在当前任务对话中完成。

## 确认服务和环境

1. 明确服务名、来源、传输类型及官方连接方式。远程 Streamable HTTP 需要经过核实的服务 URL；本机 stdio 需要 Android 上确实存在的可执行文件及参数。
2. Android 包运行的是 `codex-app-server`，不要假设存在桌面版 `codex mcp add` CLI。以当前环境变量 `CODEX_HOME` 为准，本机配置文件为 `$CODEX_HOME/config.toml`。
3. 使用可用的本地文件/命令工具检查原配置与目录权限。更新时只修改指定 `mcp_servers` 条目，保留其他服务、账号与安全设置；先备份必要原配置，检查 TOML 格式有效，再写入。需要修改沙箱外路径时按 Codex 权限机制请求用户批准。
4. 对不明来源的命令、下载安装脚本和网络端点，先核实身份与执行风险；对额外安装、外部登录及权限提升取得用户明确同意。

## 配置协议

远程 HTTP 服务形状（替换为用户确认的名称和真实 URL）：

```toml
[mcp_servers.example]
url = "https://mcp.example.invalid/mcp"
```

本机 stdio 服务形状（确保命令已安装、在安卓环境可运行）：

```toml
[mcp_servers.example]
command = "/absolute/path/to/executable"
args = ["--mode", "mcp"]
```

这些只是字段格式示例，`example.invalid` 不是可用的 MCP 地址。不得编造实际服务 URL、命令、授权信息或宣称未验证的服务已接入。

## 账号与用户授权

- `codex_apps` 是 ChatGPT 托管服务，沿用当前 Codex ChatGPT 账号；不要对其发起第三方 MCP 动态 OAuth 注册。
- 第三方服务如果需要 OAuth，由 Codex 内核认证能力处理；需要浏览器确认、账号登录或额外权限时，在当前任务内指导用户完成合法授权，并等待成功回执。不要要求用户把访问令牌、私钥或密码粘贴到对话中。
- 若当前安卓运行内核无法完成某个特定授权操作，明确报告哪个步骤受阻与所需的用户操作，保留已有配置，不以绕过认证替代。

## 验证与恢复

1. 保存配置后，通过已存在的 Codex 会话或 Android MCP 页刷新连接；必要时让系统重载 MCP 配置。当前 Android 页面会尝试在本机配置更新后重载内核服务目录。
2. 只有真正取得运行时连接并能读取实际工具或资源，才向用户报告“可用”；配置存在、令牌未知、注册请求发起、浏览器打开均不等于可用。
3. 若连接失败，检查 URL/命令、HTTP 状态、权限和内核返回；修复根因后重新验证。需要撤销失败配置时仅恢复本次修改的条目，保护其他配置。
4. 让用户到「MCP 服务」页查看可用列表；页面只展示实际可用服务的名称和可用状态。
