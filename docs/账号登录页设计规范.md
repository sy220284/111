# 账号登录页 · 四技能交叉设计规范

## 页面目标

从侧栏「偏好与设置 → 账号登录」进入，首屏按「本机账号状态 → 登录方式」排列。账号数据始终来自真实的 Codex \`account/read\`；设备码及授权网址始终来自 \`account/login/start\`。敏感凭据交给内核管理，页面仅展示用户可操作的授权步骤。

## 四个技能的具体落地

- **finesse-ui**：操作型页面优先选择清晰、密集、可读的原生 Material 3 工作台形态。延续现有深石墨、暖铜与玉绿语义色；连接状态独立于视觉强调色。主按钮只有一个，操作卡片使用细边与低对比层次。
- **finesse-brief**：每个可见状态提供明确下一步。账号状态、两种授权方法、授权进行中、失败与成功、协议原始数据均与内核真实数据关联；无数据时明确提示。
- **frame-smith**：复用工作台的 \`CodexReveal\`，仅在状态发生改变时展开或收起；遵循用户「减弱动效」设置，避免持续装饰性运动。
- **finesse-term**：统一用「设备码登录」「浏览器登录」「刷新账号状态」「取消本次授权」等准确的操作名称；验证码、授权结果与协议数据分别命名。

## 页面布局和组件

1. 首屏「账号状态」面板：身份、连接状态、认证方式、刷新以及已登录时的退出入口。
2. 两张登录方式卡片：手机端垂直排列，宽屏可双列；最小触控高度 86dp；两项操作互斥，进行中不可重复发起。
3. 设备码展示：可选中、可一键复制；授权网址按钮与操作步骤同屏展示。浏览器授权独立呈现下一步。
4. 授权中、取消中、失败时显示清晰状态；取消后可重新选择方式。成功后重新读取账号资料。
5. 原始协议响应折叠显示，默认不占用主要页面；支持选择复制，便于排障。
6. 狭窄屏幕、系统字体放大和软键盘遮挡情况下，登录方式单列且页面整体可滚动；按钮至少 48dp 高。

## 验收

- 单元测试核验设备码响应及登录完成事件的严格身份匹配。
- Android 35 模拟器检查首屏登录方式、账号刷新、折叠详情、真实截图。
- CI 同时运行 Kotlin、Lint、官方协议方法检查、Android 模拟器与完整核心启动测试。
- 真实账号授权成功及模型请求需要依赖真实账号端到端验收。
