# 111 仓库与 Claude Code 2.1.310 历史重建包的代码级差异审计

审计日期：2026-10-28

基线：`sy220284/111`，main 的 Git tree `243812d55697fe6f849738095d662600fe601b57`，共 3,628 个 tracked tree entries。仓库源码已分类迁移，主业务模块位于 `core/`，不是旧的 `src/`。本地工程基线：`Claude-Code-2.1.310-跨语言高级代码补全工程/` 及最后交付压缩包 `Claude-Code-2.1.310-Linux-x64-跨语言进程与原生回退补全版.tar.zst`。

## 口径说明

- “111 已有”意味着仓库存在对应实际代码或功能测试，不意味着与原版 ELF 完全等价。
- “111 缺失”指独立的这份移植实现尚未在基线 `main` 发现，不等于业务能力完全缺失。例如 `core/chunk-*.js` 已有剪贴板调用方，但并无独立的安全进程执行器。
- “本地可执行”与“已接入 111 默认启动链”严格区分；PR #63 的新模块目前属于前者。
- 2.1.88 旧版原生 TS 替代算法有些是近似实现，不能直接覆盖较新的 2.1.310 逻辑。
- 原版 Rust、Bun/JSC 的完整同源源码仍未恢复；本报告比较的是可见代码与已验证的替代能力。

## 二、按真实源码与 111 `main` 对比的迁移优先级

### P0：仓库缺失、能够独立测试、已经发起 PR

1. `runtime/linux/process-transport.mjs`：来自本地 `源码/运行时高层实现/process-transport.ts`。统一执行无 shell 子进程，处理 SIGKILL 进程组、timeout、stdout/stderr 上限和输入输出字节缓冲。
2. `runtime/linux/clipboard-linux.mjs`：来自 `clipboard-linux.ts`。Linux Wayland/X11 读取顺序、2000ms 执行限制、可选 N-API 回退、PRIMARY 写入代次防旧任务覆盖。
3. `runtime/linux/lazy-image-pipeline.mjs`：来自 `lazy-image-pipeline.ts`。一次解码、惰性处理 resize/jpeg/png/webp。
4. `runtime/linux/imagemagick-image-processor.mjs`：来自 `imagemagick-image-processor.ts`。调用真实 ImageMagick，且继承安全执行器的超时/输出预算；**依赖系统 magick**，不是原生编码算法源码。
5. `tests/linux-portable-backends.test.mjs` + `package.json`：10 个 Node 22 本地真实测试，已加入 `npm test`。`magick` 缺失时相关测试显式 skip；本地具备该工具时 **10/10 passed**。

GitHub PR：<https://github.com/sy220284/111/pull/63>。PR 将其添加为可显式调用的独立库，没有把它们宣称为已经接管默认 CLI。

### P1：111 缺失实际替代实现，但不能未经适配就合并

| 本地真实代码 | 111 的现状 | 迁移前必须完成 |

### P2：谨慎采用的旧版 TS 算法

| 2.1.88 参考算法 | 本地已有成果 | 111 目前已具备 | 建议 |
|---|---|---|---|
| Shell Bash Parser + AST | 完整旧版 TS 参考与测试 | 2.1.310 原始业务 chunk 中有自己的解析器 | 不回退代码，只将旧版测试与新版语义缺口做差异回归 |
| Yoga 布局 | 旧版纯 TS 参考，实现不完整 | 2.1.310 chunk 中已有新版布局模块 | 仅修复行为不一致处；缺少调用链时不要提交完整旧库 |
| FileIndex | 旧版匹配算法及新版 2.1.310 facade | 新版含匹配位置、文件名权重和构建版本控制 | 禁止覆盖新版；若保留旧版可作可测的替代算法实验 |
| ChromeNativeHost | 旧版独立 TS native messaging host | 新版已有 JS 宿主实现 | 迁移旧版测试条件/消息协议，非重复加宿主 |
| ColorDiff / SGR / OSC | 2.1.88 的颜色和终端语义对照；部分算法已有独立提取 | 2.1.310 保留自身高亮与终端处理代码 | 优先单独提取经过差异验证的缺失分支 |
| 原 JS/TS 源码与 2.1.88 source map | 当作证据与参考 | 111 已有完整主模块与自己的研究结构 | 不把参考源或 map 全仓复制进主仓库 |

## 三、111 已有，无需重复提交

- 2.1.310 主 JS 模块恢复、CLI 入口、资源分类加载器，以及 2 个原版 Linux `.node` 二进制。
- Agent/MCP 的基础真实本地模型 SSE 与 MCP 工具调用测试；Daemon、Hook、Session、权限相关已有大量源码级和实际运行测试。
- Bun/JSC 静态 API 审计、Jelly 代码图谱、Ghidra 12.2 + JDK 25 反编译工作流、离线工具链。
- 2.1.88 源码中已被 2.1.310 恢复模块实现的 Bash、索引、布局、Chrome 等业务逻辑，不应做降级覆盖。

## 四、迁移顺序与硬门槛

1. **PR #63**：独立兼容 ESM 和 10 个回归（已提交，未直接接管 CLI）。
2. **下一组原生 PR**：C N-API 的编译、导出 ABI、错误路径、跨进程运行测试；作为替代实现，保持原版二进制不变。
3. **CellSegmenter PR**：Unicode/ANSI/bidi/宽字符单元的可重建实现与 2.1.88 交叉验证；必须增加实际绘制数据对照才能改业务入口。
4. **CLI 整合 PR**：把经验证的 Linux 兼容模块通过受控特性开关注入 111 启动链；必须按原版 ELF 做多命令和 MCP/Agent 对照。
5. **环境缺口**：Wayland compositor、真实音频硬件及云端 Agent 的等价测试，未达到则不标记全量完成。

## 五、避免错误统计

- 2.1.88 老 TS 参考文件数量，不等于 2.1.310 新增了等量功能。
- 原 Ghidra C 伪代码不能编译、不等于原生 C/C++ 源码，不迁入代码分支。
- “CLI 14/14”多为固定命令对照，不等价于完整在线业务验收。
- 新的 PR 的 ImageMagick 能执行不表示已经去除 native 编解码依赖；它仅封装真实系统级处理程序。
- 独立测试已通过不代表主 CLI 已调用新模块，后续必须补调用链证据。
