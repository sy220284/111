# 111 Android 全路由交互反馈与运行链路优化（2026-11-22）

## 输入证据
以主分支 `040184e97e85e33d75b504efc6bccc07acc12cfe` 的 Android 35 360/393/411dp 模拟器截图各 51 张（工作流 `44912997375`）为基线。校对 `UiFeatureCatalog` 的全部 29 个实际页面路由和 `UiProtocolMatrix` 的 195 项原生请求矩阵；四项设计技能按产品工作台、状态驱动动效、通俗术语及使用场景选择，不将视频制作逻辑直接移植到 Compose。

## 本次实施
1. **全页面真实写入反馈**：`CodexViewModel.rpc` 只在真实服务端成功后发出结果回执；失败时保留原始页面错误并发送清晰中文提示。所有经过该入口的设置、会话、插件、权限、MCP、服务商、审查等动作统一显示于界面，普通后台读取不弹出成功消息。
2. **工具调用错误**：MCP 调用即使 HTTP/JSON-RPC 成功，若业务返回 `isError=true`，展示错误而非操作成功。
3. **会话切换安全**：完成 `thread/read` 并构建历史记录后才切换到目标会话；读取失败保留原会话及执行时间线，解决跳转后丢失上下文的隐患。
4. **连接恢复**：内核重新连接成功后清除之前的连接错误。
5. **全局动画与反馈**：统一 110ms 按压动效、具有明确动效减弱开关的主要操作按钮、长操作按钮繁忙态、180ms 标题变更渐显；Snackbar 集中展示实际操作结果。
6. **空状态**：空态组件统一图标强调、标题说明及明确的主要操作，跨页面复用，空屏更加可读。
7. **验证**：新增纯 Kotlin 协议提示测试覆盖成功、服务端工具错误、业务失败与未知方法；保持 29 个路由原样，CI 编译、单测、Lint 与设备截图不能回退。

## 边界
所有状态来自实际 `CodexConnection` 返回或本地真实用户操作；不对高级/实验请求生成模拟执行入口。ARM64 物理机、真实 OAuth、云端长任务与复杂 MCP 调用仍需实际账号和设备端到端验证。Figma 文件 `K4FEMoNdmQbcnJZCHWr8c7` 当前 Starter MCP 已达到调用额度，暂不能提交画板修改。

## 视觉基线与验收
维持桌面式侧栏、典雅白、高级工具收进上下文、低干扰反馈策略；强操作提供可见结果与失败恢复，动画尊重系统与应用减弱动效选项。后续变更须以对应提交上的 CI 截图及端到端日志证据作为完成依据。

## 跨页二次完善
- 内核断连与启动中的反馈由红色错误收敛为可行动的提醒；同页多个 API 报告同样的断连错误时只呈现一项。
- 仅在服务端已返回实际列表数据时才显示“没有技能/钩子/连接应用/MCP 服务”的空态，不把网络故障误写成没有安装。
- MCP 工具的普通参数表单与 JSON 专家输入可以互相转换并保留用户已输入的字段值；缺少明确标题时优先读取字段原义。
- 权限保存与 MCP 调用按钮具有请求执行中状态；通用列表的刷新图标具有 48dp 点击区与实际载入指示。
- 业务错误提示移除 RPC 方法名的技术前缀，保留真正失败原因；详细诊断仍保留在运行核心日志中。

## API 参数闭环补充
技能、运行钩子和插件的工作区目录请求使用同一 `CatalogRequestContract.workspace`，修复原来首次读取带 `cwds`、出错重试却丢失 `cwds` 的链路；MCP 的首次读取、工具刷新和失败重试统一使用 `mcpStatus`，保留 `detail=full` 和当前会话 ID，确保工具表单与资源字段一致。模型、服务商、队列等空状态仅在真实服务返回后展示；模型列表展开动效尊重减弱动画开关。
