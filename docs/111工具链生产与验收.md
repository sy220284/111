# 111 工具链生产与验收

以 tools/dev/toolchain-lock.json 为现有版本约束。777 共享组件固定来源 SHA、Actions 产物 ID 和 SHA-256；111 独有工具链由 dev-toolchain.yml 在变更或手动触发时生产，不新增定时任务。

- 共享组件：`python3 tools/dev/ai-toolchain.py shared-install --artifacts-dir ./toolchain-downloads --download`，需要已经授权 GitHub CLI。
- 111 独立组件：由相同运行下载组件及 manifest-pin，使用 `python3 tools/dev/component-bundle.py install <component> <bundle-dir> <install-root> --manifest-sha <已核验的manifest SHA-256>`。组件按摘要隔离，逐片校验，拒绝越界链接和污染目录；安装产物不覆盖系统 SDK。
- Android 组件分别生成 JDK、Android SDK/NDK、Gradle Wrapper 和 Maven 缓存；在隔离网络的新安装目录运行实际 debug、androidTest、release、Lint 和单测。Gradle 依赖基线已由 #116 提交，生产与断网验收均严格校验，拒绝重新生成替代原锁。
- Rust 组件包含固定 1.99.1 和 Android 两 ABI 标准库、Cargo 源与 Git 依赖缓存；独立离线验证 fetch。V8 仍由现有精确指纹的独立生产和验证流程负责。
- 777 移动端准备脚本固定复制自 15437765368eecfbdbee7d9e372a74195efff0e4。ARM64 使用固定归档中的已签名 Termux 包，按原版本检查；x86 使用官方签名的独立组件；2026-11-23 官方 ripgrep 更新到 16.0.0（Termux 3ad460e73d924ca38cdfded88373e8213f149dde），因此只对 x86 精确锁定 16.0.0，ARM64 保留 777 已验收的 15.2.0。其余版本仍须严格相等，实际包摘要与依赖闭环需通过同候选 CI。
- 双 ABI 产物统一由 `prepare-developer-runtime.yml` 提取、装配、回读；统一验收和正式发布消费该工作流输出的 manifest pin。独立命令启动器为每组 CLI 设置依赖搜索路径，避免 Python、Node、Git 动态库交叉污染；Git、rg 不再重复编译。真实设备执行和签名发布仍按 AGENTS.md 门禁执行。

## 统一安装和调用

下载同一次已验收工具链运行的组件与清单摘要（各组件目录保留 artifact 名称）。使用 `bash tools/dev/ai-toolchain.sh host-install --artifacts-dir <目录> --pins-dir <受信摘要目录> --source-sha <生产提交>`，然后使用 `host-env`、`gradle :app:testDebugUnitTest` 或 `cargo fetch --target aarch64-linux-android`。已有 Gradle/Cargo 可写缓存与安装回执匹配时复用；明确修复用 `--repair` 重装。CI 同样使用这一安装入口；Gradle/Cargo 调用固定离线及依赖校验。同一构建环境不混用不同提交产物。

远端按需安装：`bash tools/dev/ai-toolchain.sh host-install --run-id <已完成运行ID> --components jdk android-sdk gradle`。运行需由本仓库工具链工作流产生，选中组件对应的实际断网验收任务必须成功；核对最新尝试、提交 SHA、产物创建时间、ZIP SHA-256、清单摘要和内部内容。已有同摘要组件只取回小型清单，避免再次下载大包。

## CI 与发布共用生产链

`prepare-host-toolchain.yml` 根据 Android Gradle/SDK 或 Rust 依赖输入生成指纹；同指纹串行生产，仅复用真实断网任务成功且文件仍可访问的原始产物。统一 CI 与签名发布通过固定产物编号安装，逐一验证 ZIP、组件 manifest 和文件；Android 构建使用 `--offline --dependency-verification strict`，原生项目 Cargo 使用 `--locked --offline`。V8 官方源码生产仍由其独立核验流程处理。

辅助组件独立组：wheelhouse（CI Python 3.12 与官方发布工具锁）、uv（五个上游 uv.lock）、pnpm（上游 packageManager SHA-512 与完整 workspace store）、Bazel（9.3.3 与 Linux 原生核心/维护目标依赖）、emulator（37.2 16KiB）、LLVM 21（带 libclang 和实际编译探测）、HDiffPatch 5.1.3。均通过同一指纹/验收产物机制生产；Bazel Windows/MSVC 和 macOS 专用 SDK 不在 Linux/Android 交付范围内。每组须取得实际断网验证成功后才可被消费。
