## 统一安装和调用

下载同一次已验收工具链运行的组件与清单摘要（各组件目录保留 artifact 名称）。使用 `bash tools/dev/ai-toolchain.sh host-install --artifacts-dir <目录> --pins-dir <受信摘要目录> --source-sha <生产提交>`，然后使用 `host-env`、`gradle :app:testDebugUnitTest` 或 `cargo fetch --target aarch64-linux-android`。已有 Gradle/Cargo 可写缓存与安装回执匹配时复用；明确修复用 `--repair` 重装。CI 同样使用这一安装入口；Gradle/Cargo 调用固定离线及依赖校验。同一构建环境不混用不同提交产物。

远端按需安装：`bash tools/dev/ai-toolchain.sh host-install --run-id <已完成运行ID> --components jdk android-sdk gradle`。运行需由本仓库工具链工作流产生，选中组件对应的实际断网验收任务必须成功；核对最新尝试、提交 SHA、产物创建时间、ZIP SHA-256、清单摘要和内部内容。已有同摘要组件只取回小型清单，避免再次下载大包。

## CI 与发布共用生产链

`prepare-host-toolchain.yml` 根据 Android Gradle/SDK 或 Rust 依赖输入生成指纹；同指纹串行生产，仅复用真实断网任务成功且文件仍可访问的原始产物。统一 CI 与签名发布通过固定产物编号安装，逐一验证 ZIP、组件 manifest 和文件；Android 构建使用 `--offline --dependency-verification strict`，原生项目 Cargo 使用 `--locked --offline`。V8 官方源码生产仍由其独立核验流程处理。

辅助组件独立组：wheelhouse（CI Python 3.12 与官方发布工具锁）、uv（五个上游 uv.lock）、pnpm（上游 packageManager SHA-512 与完整 workspace store）、Bazel（9.3.3 与 Linux 原生核心/维护目标依赖）、emulator（37.2 16KiB）、LLVM 21（带 libclang 和实际编译探测）、HDiffPatch 5.1.3。均通过同一指纹/验收产物机制生产；Bazel Windows/MSVC 和 macOS 专用 SDK 不在 Linux/Android 交付范围内。每组须取得实际断网验证成功后才可被消费。

统一 CI 的 Pillow/jsonschema 依赖改为经校验 wheelhouse 安装；八个 UI 分片与真实 x86 内核验收改为消费已打包的 37.2 模拟器镜像，保持原设备配置与原测试脚本；APK 与签名发布使用已核验 HDiffPatch ZIP，V8 源码生产使用独立 LLVM/libclang。各消费任务必须依赖对应已验收产物，不能由宿主机安装代替。

## 长期保存与真正断网构建

在 Actions 产物有效期内，可将已经实际验收的组件及固定摘要导出到用户控制的磁盘或制品存储：

```bash
python3 tools/dev/ai-toolchain.py host-export --run-id <验收运行ID> --directory ./archive-111 --components wheelhouse uv patcher
python3 tools/dev/ai-toolchain.py host-install --artifacts-dir ./archive-111 --pins-dir ./archive-111 --source-sha <导出返回的sourceSha> --components wheelhouse uv patcher
```

保留导出时返回的 indexSha256 作为独立可信记录，并与 archive-index.json 比对。归档带原始分片、清单、来源提交、产物编号及摘要；安装不再需要访问 Actions。不在未授权的公开发布区分发 Google SDK 或设备镜像。正式 Gradle 与原生 Cargo 编译在仅有 loopback 的网络命名空间运行；模拟器联网用例仍使用原实际设备测试网络。Bazel 仅归档内容寻址下载缓存，生成的外部仓库重新在本机展开，禁止携带宿主机绝对链接。
