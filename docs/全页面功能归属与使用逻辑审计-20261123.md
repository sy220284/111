# 111 安卓版全页面功能归属与使用逻辑审计（2026-11-23）

> 历史 29 项路由审计；现行功能登记为 32 项，实际容器以 UiFeatureCatalog、路由实现和接口台账为准。完整会话资料库已独立为页面，任务选择仍走上下文 Sheet；旧管理弹层、Android 35 三档仅限原审计。

## 基线、范围和统一判断

基线：PR #61 `ux/main-entry-settings-dsh-20261123` 提交 `7c1a6bf`。接续已合并的 PR #55；本次审计以分支 `ux/full-page-contextual-audit-20261123` 为代码交付，目标是修复仍存在的页面归属、重复入口和后台信息暴露问题。

逐项核对 `UiFeatureCatalog` 全部 **29 个注册入口**，以及导航、设置搜索、Android 页面实现和主要子组件。按四个判断：用户是否需要专门页面、功能是否属于任务或工作区、入口是否重复、展示信息能否直接帮助用户决策。保留真实操作能力及协议调用；归属不同的功能使用独立可关闭的工作区或弹层。

## 子页面与跨页面链路

- 文件编辑、导入 ZIP、复制、重命名、删除确认仍在项目文件工作区完成；新建文件夹和文本文件无需离开文件列表。
- 插件详情沿用能力视图；MCP 授权和外部表单留在请求上下文。**普通字符串列表改为逐行填写并转换成内核所需数组**；仅特殊数组保留明确标注的高级数据输入。
- 账号登录选择、设备码和浏览器授权保留；账号使用量和额度共享切换标签，旧 `limits` 路由仍可打开额度标签。设置搜索“额度”“用量”只返回同一管理入口。
- 诊断中真实启动日志仍可按需展开，关键状态和处理动作优先可见，协议字样从默认页面移除。
- 权限、外部设备、服务商、插件安装和配置写入继续沿用原有确认、安全检查和 ViewModel 协议调用。
- 对话区的审查、差异、任务目标、队列、模型和协作模式按现有上下文弹层逻辑处理，避免重建“功能总菜单”。
