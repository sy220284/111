# 111 统一 CI 交付流程

> 本文为 #116 联合候选的实际 CI 设计及历史演进；当前 main 仍使用 Android 35 三档，尚未合并本候选。当前 API37 设备矩阵只含主流、旗舰两档各基准/适配，每配置导航/组件两分片，共八组 UI 与独立 x86 实核。以 android-app/tools/device-matrix.json、ci.yml、同候选实际回执为准；完整工具链与联合 CI 仍待通过，见 [现行实现索引](现行实现与文档维护索引.md)。

生产入口为 ci.yml，所有 PR 和 main push 均由唯一分类规则决定检查范围。原生工作流同步调用并等待实际结果，ARM64 缺失时补编译；UI 两档及协议、Lint、APK 二次核验、签名冒烟、上游预演均保留。质量门禁以 111 合并验收为固定状态，正式发布只接受 main 同提交完整通过。

原生索引按内容指纹检索，同时检查产物、祖先关系、真实编译和 Rust 回归。测试及编译输入变化都需重新核验。历史产物仅在原配方完全一致时可复用。

正式发布先锁定候选，生成正式签名 APK，核对上版证书，生成完整及增量资产；专用 ARM64 设备验收后，草稿上传、回读、哈希核验、公开、清理。正式 APK 与设备实际安装文件必须字节相同。

## 必要基础设施（上线前必须配置并实际验证）

- GitHub main 保护：必需检查 `111 合并验收`，禁止直接推送并要求分支最新。
- GitHub 环境 `arm64-release` 仅允许 main，保护专用设备；专用 self-hosted Linux Runner 标签 `111-release-device`，连接隔离 ARM64 实机，配置 ANDROID_SERIAL。
- Runner 预置独立外部设备测试工具，环境变量 CODEX_DEVICE_TEST_HARNESS 指定绝对路径。工具必须实际执行 seed/verify 命令，并输出版本、APK SHA256、每项检查真实结果。检查合同见 verify_device_evidence.py。工具及测试账号尚须设备管理员配置，禁止用伪造 JSON 替代。配置完成后才可设置仓库变量 ARM64_RELEASE_RUNNER_READY=true。
- 缺少设备基础设施时流程保留已签名候选并明确失败，旧版本继续可用。
- 上游导入使用手动主分支入口；创建中文草稿 PR 后主动 dispatch 统一 CI，同提交签名检查纳入验收。未完成统一验收的 PR 不得合并。
- 竞品研究工作流保持独立手动入口。不新增定时任务。

原生历史迁移仅登记经编译日志、源代码树、Rust 回归和产物摘要交叉核实的 run 45568181115。新构建使用指纹索引，无历史扫描上限；Actions 产物受 90 天保留期限制，过期自动补编译。专用设备 Runner 应限制为受保护发布工作流专用，公开仓库的 PR 不能获得该 Runner 调度权限；如果仓库级 Runner 无法落实隔离，需独立的可信发布执行环境。

所有产品代码变更的完整 CI 均要求 x86_64 真实核心专项，与八台 UI 模拟器及 ARM64 打包并行；未改变实际输入时仅复用同仓库已验证的成功原生及专项凭证，纯维护变更仍不触发全量。统一门禁本身有失败、取消、漏跑、未知任务、文档提交及手动运行的自动回归用例。

编译和 Rust 回归使用独立指纹与独立凭证索引。只改变回归规则时，复用匹配的 ELF、补跑 Rust 测试；只有编译输入改变或产物过期才补编译。

## 2026 Android 17 设备矩阵

所有生产 UI 和真实核心模拟器升级为 Android 17（API 37），统一使用 Google APIs 16KB 页镜像。公开仓库标准 Linux Runner 为4核、16GB内存；每台模拟器统一配置4 vCPU、8192MiB RAM（官方命令行上限）、8192MiB数据盘，Mesa工作线程上限为4，余下宿主内存供系统和渲染使用。UI分流与真实内核专项共享同一配置，启动后以实际在线CPU数及MemTotal核验资源并保存JSON；内核保留内存不计入MemTotal，低于配置值7/8或CPU数不符阻断验收。测试 OS 更新不改变应用的 compileSdk、targetSdk 和 minSdk。

| 档位 | 基准像素 | 显示密度 | 逻辑宽度约 | 适配场景 |
|---|---|---|---|---|
| 主流大屏（OnePlus 15 尺寸参考） | 1272×2772 | 480dpi | 424dp | 1272×2400、480dpi、1.3倍字体 |
| 高分辨率旗舰（Galaxy S26 Ultra 尺寸参考） | 1440×3120 | 520dpi | 443dp | 原始分辨率、1.5倍字体 |

密度是测试选择，用于模拟不同显示缩放，非各厂商原厂系统默认值。两档分别执行基准和适配轮，保留各轮完整适用用例；系统安装器专项在主流大屏执行。运行报告与截图清单记录实际系统版本、页大小、分辨率、显示密度、字号和逻辑尺寸，旧 API 35 证据不得作为 API 37 的通过凭证。正式 ARM64 真机须实际运行 API 37。竞品参考采用同一主流配置。

系统与屏幕配置来源：Android 官方 https://developer.android.com/about/versions/17/get；Chromium Android 17 16KB 镜像说明 https://chromium.googlesource.com/chromium/src/+/main/docs/android_emulator.md；OnePlus 15 官方规格 https://www.oneplus.com/global/15/specs；Samsung S26 Ultra 官方规格 https://www.samsung.com/sg/business/smartphones/galaxy-s/galaxy-s26-ultra-sm-s948bzkbs02/。

模拟器创建后、启动前按同一矩阵设置 AVD 原生 LCD 宽高与显示密度，避免用低分辨率设备仅拉伸逻辑窗口；分片启动后只读校验实际基准分辨率、密度和字号；适配轮次在测试应用进入前台后单独写入有差异的参数。截图清单另记录每张 PNG 的实际宽高。

Android 17 的运行时镜像包固定为 `system-images;android-37.2;google_apis_ps16k;x86_64`（Chromium 当前配置）；模拟器工具的 SDK platform 参数独立保持 35，实际设备 SDK 必须为 37。设备矩阵和真实内核运行脚本的独立修改仅运行基础检查，可通过手动全量验收验证真实设备，保留不少于150项 UI 测试的底线。模拟器启动后的原生 LCD 参数需与基准配置一致，避免以低分辨率物理屏拉伸替代。Android Emulator Runner 锁定已核实支持独立镜像参数与 16KB 目标的提交。

## UI 体验专项验收

原145项 UI 测试增加5项真实生产页面几何、触控、IME、字体、跨页面草稿恢复，共不少于150项，每档两轮，四种配置合计不少于591次（147×4+3）。每档另执行1项真实帧性能测试，在开启系统动画时连续4轮物理触控导航，记录 FrameMetrics 总耗时、帧截止时刻、刷新率、超期及慢帧，并保存帧的预期垂直同步时间和操作阶段起点，供逐帧归因，并阻断样本不足和严重卡顿（P95 >120ms 或 >100ms 帧占比超过15%）。该阈值仅用于 CI 模拟器严重退化，真机高刷新率体验仍需独立测量。截图内容、来源、分辨率、色彩非空及历史视觉变化自动审计；历史差异报告用于审阅，有意设计变更仍可接受；新系统首轮明确 baseline_pending，成功 main 产物形成后续对照。真实账号、远端工作区、厂商权限、系统级弱网及真实性能仍依赖专用实机/服务环境，不以 UI 样例冒充。

真实帧专项使用 ActivityScenario 独立启动生产 Activity，通过系统无障碍节点定位和物理触控进行实际导航；不使用 Compose 测试虚拟时钟。

真实核心专项新增一次无外部账号的端到端网络恢复：本地真实 HTTP 服务先返回503，再产生实际读超时，随后恢复200；通过原生 Codex command/exec 执行 curl，要求退出码22、28、0及最终业务内容正确，且同一核心仍可响应。视觉对比同时锁定 Android 实际 build fingerprint，自动生成所有需要审阅场景的旧、新、差异缩略图。

## 并行执行与跨设备一致性门禁

静态协议与视觉检查独立于 Kotlin 编译/单元测试/Lint，两个任务并行。UI APK 仍只编译一次并共享。两档基准及两档适配共四种配置，每种配置拆分为导航和组件/子页面两台独立模拟器，8 台并行；导航组执行 UiNavigationInstrumentedTest，组件组执行其余四个 UI 测试类，系统安装器独立契约和实际升级继续由主流基准组件组执行；动效由两档基准导航组执行。四个汇总任务分别核验两组同提交、几何、互不重复的实际运行 ID 与用例集合、原始截图完整性及无冲突，再生成原有完整截图集、独立视觉审计和历史同模式对比。最终门禁核验全部四种配置的完整用例集合与八个独立运行 ID，任何缺失、重复、失败或截图冲突均阻断验收。ARM64 二次核验与 x86 真内核运行独立，不互相阻塞；合并门禁和发布验收仍要求所有适用任务成功。原生构建本轮未变更，继续复用已验证原生凭证。实际节省时间以 CI 记录为准。

## 验收去重与输入证据复用

七组职责：静态审计、UI 编译/四种配置实测及证据、原生和 ARM64 打包核验、脚本预检、上游兼容、真实 x86、PR 签名。对完整 Git 文件树相同的祖先 PR，已实际成功的组可由 main 继承。对不同文件树，只允许明确审核过的无关路径变更，其他路径默认使相关组重新执行；每次手动全量无复用。复用来源必须同仓库、祖先提交、CI 完成成功、原作业实际成功、七天内且要求的产物仍未过期、具有有效 SHA256 摘要；不继承仅曾复用的组。计划凭证含目标树、源树、运行编号及产物摘要，合并门禁重新获取核对，发布再独立验证；缺失、过期、改动或无法证明均须真实执行或阻断。GitHub 环境镜像仍由平台维护，有界复用窗口控制漂移风险，正式签名包和 ARM64 真机仍完整独立验证。

三项安装器 Intent / PackageManager / FileProvider 契约仅主流基准执行；其余 UI 测试全部四种配置执行，确切测试身份集合及三项平台用例单次完整执行都进入门禁。基于150项底线，交互执行次数为591（147×4+3），新增长用例自动提高实际次数。保留两档设备各自的完整截图和基准动效；紧凑旗舰及其360dp适配轮退出自动验收范围。原生输入签名同时控制同输入编译串行，旧 PR 的昂贵编译不被无关更新取消；可能同时运行旧版轻量 CI，按证据优先避免重复原生构建。完整 APK CRC/架构/文件/哈希由审计器完成一次，独立下载核验同一字节摘要。静态审计保留各项既有独立规则，仓库脚本测试按唯一归属执行，原生独立构建保留适配器自检以保障单独调用安全。

静态审计统一由 `android-app/tools/run_static_audit.py` 调度：协议、功能、设计三个入口共享一次源码及协议索引；原有规则、报告和负向回归测试全部保留。`static-audit-summary.json` 记录各类别结果，任意类别异常均阻断验收。禁止将静态源码通过作为真实设备或真实内核通过的证据。

## 零额外云设备费用的测试体系

- 日常完整 CI：八台 x86_64 UI 模拟器和一台 x86_64 真实内核模拟器，统一 Android 17、4核、8GiB 内存、16KiB 页大小，全部适用用例及门禁保留。公开仓库使用现有 GitHub 标准 Linux Runner；只复用验证通过的同输入证据。
- 正式发布：沿用 ARM64 实体手机与专用 Runner 的真实签名安装、升级、账号、远端工作区、权限及异常恢复验收。实体设备未就绪则保留候选并阻断公开，不能用 x86 模拟器替代。
- 取消收费 Google Developer Device Platform 原生云设备方案；源码中不保留云端调度、认证、专用测试与发布依赖，不配置云账单或云资源。ARM64 原生虚拟设备暂不接入、不计入已完成验收；后续仅在确认无额外费用且满足 Android 17、ARM64、16KiB 要求后再评估。当前共九台 CI 模拟器，另有独立实体机发布门禁，不要求付费云环境。

免费模拟器九组统一采用 SwiftShader GLES（禁用 Vulkan），基准动效明确使用 Skia OpenGL 并核对实际管线；汇总从原始帧重新计算 P95 与慢帧比例，阈值不变。满配置 lavapipe Vulkan 实测失败，保留原失败证据；新路径必须重新实测通过，真机 GPU 性能仍独立验证。

增量凭证 v2：Android 编译与设备 UI 分开验收；设备组使用明确来源的 APK 与 SHA-256 文件。成功组可来自整体失败/取消但已完成的历史运行；仅复用实际完成且同仓库祖先、依赖未变、运行批次及产物摘要完整的结果。保留最终 111 合并验收及真实运行时依赖。产品动效时长与透明度不变，屏幕遮罩改为绘制节点，聊天顶栏独立订阅；以两档基准设备实测判定收益。

原生同输入队列采用 GitHub concurrency queue:max，各候选按完整提交 SHA 独立启动验收，同一候选重复触发仍串行；原生、V8 和主机组件按内容指纹串行生产并严格复用，使新候选的静态、编译和 UI 检查可先行暴露问题。独立 CI 队列管理仅对同仓库同 PR 已被替代或关闭的验收请求取消；保留当前候选、手动验收、正式发布和独立原生工作流。检查产物由 GitHub 按配置保留期限到期处理；分支与缓存由平台设置或人工管理，不运行仓库管家或自动清理。动效证据增加前后宿主压力、CPU、内存和客机信息。

联合验收 v3：历史运行仍在执行时可复用已完成的独立组；实际作业身份和产物时间窗纳入凭证。下载 UI APK 按不可变产物 ID。V8 独立生产者按架构/源码/配方加锁，可信原始产物复用不依赖核心编译成功；核心链接前二次检查实际字节与来源。所有功能和设备门禁维持原标准。

UI 分片复用只从本次可信编译来源的直接成功模拟器作业读取历史证据。实际两个 APK 哈希一致、测试输入未变且 ZIP 摘要、来源提交、作业与运行批次完整时，可跳过该分片的再次设备启动；失败或缺失仍执行。汇总复核原始来源、实际用例集合、截图及完整矩阵的 APK 字节一致性。

### UI 动效工作负载隔离与性能证据边界（2026-11-27）
- 高频抽屉保留原生位移、遮罩和稳定首屏组合，关闭时阻断焦点/无障碍入口及搜索、归档、分组请求，释放临时选择和弹窗；目录索引缓存由会话控制器持有，账号失效时替换。真实数据仍可更新，不冻结安全状态或以整页位图替代交互。
- 动效进度在布局放置/绘制/图层阶段消费；排序、过滤、索引及其他重计算在后台处理，按稳定身份提交界面数据。扩展到页面、弹窗、列表、流式回复时分别测量首屏构建和稳定动画，避免为缓存引入无限驻留或整面离屏缓冲。
- 无物理 GPU 的 CI 使用 SwiftShader，宿主与模拟器共享 CPU；绝对帧时间及设备档位差异仅反映软件渲染压力，不能作为真机流畅度、GPU 性能、功耗结论。同配置多轮对照用于发现回归，原 120ms P95／15% 慢帧门槛及所有原始帧、真实触控和截图验收保留。每帧各阶段原始耗时与预期 vsync 对齐保存，区分输入、组合/动画、绘制、提交及等待，百分位不可相加。
- 真机性能独立登记：相同签名候选 APK、相同场景/会话数据和刷新率，记录设备/系统/GPU、温度、编译模式、空闲及流式负载；分别测冷/热开抽屉、页面切换、滚动和更新，报告帧截止超期率、P50/P95/P99、输入到可见反馈时间；Perfetto 采样用于分离主线程、RenderThread、GPU 与系统调度。60/90/120Hz 分别以约 16.67/11.11/8.33ms 帧周期为参考，按实际 FrameTimeline 截止时刻判定。软件模拟器失败保留，真机未测明确待验，不以设备型号或模拟器通过宣称真机通过。
- 补充落实：抽屉位移期间只暂缓同一账号/会话/筛选范围内的目录投影；动画完成立即处理最新输入，数据失效直接清空，账号或范围切换不复用旧展示。运行、审批、权限等状态不冻结。独立记录四次打开中首次和后续三次的帧耗时，不从验收样本剔除首次。
- 实体设备入口：在专用测试机安装同候选应用 APK 和测试 APK 后执行 `python3 android-app/tools/run_ui_motion_checks.py --physical-device`，保留设备默认图形管线，拒绝模拟器/明显软件渲染，采集设备/GPU/温度、P50/P95/P99、实际帧截止超期率和逐轮开抽屉数据；原严重回归门槛仍执行。真实 GPU 入口输出为独立证据，需结合多次同设备测量及 Perfetto 复核，不冒充完整真机体验验收。CI 的 `--profile` 路径不变。

## 现行：用户工具链独立交付，CI 使用官方环境

用户工具链仅手动执行独立 dev-toolchain 工作流。验收、原生构建和发布不再生产或安装用户宿主组件，不再下载 JDK/SDK/Gradle/Rust/Cargo/模拟器/LLVM/wheelhouse/patcher 整包。CI 使用 GitHub 托管 Runner、官方 SDK/Rust/Gradle 工具和依赖缓存，按缺项安装；Android 37.2 镜像与真实设备硬门槛不变，严格依赖锁与来源验证保持。APK 实际包含的原生核心、V8 和手机运行时仍为产品产物。此节取代此前的宿主工具链预生产描述。

### 官方环境与缓存边界

- 编译使用 Runner 预装 JDK 25 与 SDK；仅缺失的官方包才安装，Gradle Wrapper 与 Cargo 使用官方依赖缓存，Python 缓存下载文件但每次仍按摘要锁安装。无需生产或下载标准工具链整包。
- 模拟器在设备验收作业内使用 Runner SDK，独立缓存仅包含设备矩阵指定的系统镜像目录，键由系统镜像 API、类型与 ABI 决定；设备尺寸、测试及普通 CI 改动不使镜像缓存失效。预装镜像直接使用，缓存未命中才从官方 SDK 安装，实际启动、API、16 KiB 与功能验收不变。真实内核 APK 先构建，成功后才准备模拟器镜像。
- V8、原生核心及手机运行时仍按现有专用产物契约装配并核验。用户下载的宿主工具链继续独立手动维护，不成为 CI 输入。

手机运行时按 ABI、产品依赖锁、原生装配脚本和构建配方生成唯一输入键。优先复用同仓库统一验收中实际生成且通过核验的原始产物，消费者直接按不可变 ID 下载并核对 GitHub 摘要及包内清单；验收或发布不再重新生产相同运行时，也无需在复用作业中重新上传。无合格产物时才构建。原生和设备功能验收仍执行。

公共构建脚本归入 `tools/build/`；`tools/dev/` 专供用户工具链生产与安装，独立变更不触发产品全量构建和发布。常规 CI 仅引用公共构建与产品运行时脚本。

V8 独立构建仅受应用锁文件中的 V8 包记录、V8 官方固定源码、实际编译脚本和编译器配置影响；与 V8 无关的 Cargo 包版本变化、Gradle 缓存和 Cargo 缓存传输参数不再单独使 V8 产物失效。原生内核仍依据完整 Rust 源码、依赖和实际编译配方核验。

模拟器镜像缓存独立核对 SDK 官方包名、版本元数据与文件摘要；缓存命中时核验原始文件完整性，不重复安装或封装整个 SDK。运行时跨提交复用还要求原始 CI 调用作业一致、实际产品输入一致及直接生产作业成功。

## 职责独立与按输入验收（统一调度 v4）

- 统一验收始终覆盖全部适用组；独立检查脚本按其明确消费者失效，未知变更仍全量。七天内原始实际成功、祖先关系、作业批次、文件树差异、有效产物摘要均通过时复用；手动强制全量不继承验收组。
- 原生构建是 ARM64 打包和 x86 真实运行两个独立验收组的共享前置。仅 x86 需要重新验收时，保持 ARM64 APK 的有效历史凭证，只请求 x86 内核；反向同理。两组均执行时统一请求双 ABI。原生回归和编译证据继续严格核验。
- V8 生产作业先仅查询原始成功产物编号。命中时跳过 SDK/Rust 准备、下载、编译和上传；原生消费者直接下载历史原始产物并检查摘要、文件集合和构建来源，若无完整合格产物则实际重新生产。首次迁移编译配方可能建立新指纹，不能以旧凭证替代新配方。
- 用户工具链手动工作流仅生产独立主机工具和辅助组件，用户所需共享包仍按锁安装；APK 手机运行时只由产品链路生产。正式发布先核对是否已发版、是否实际有发布输入变化，再查询原生核心，避免空发布查找大产物。
- 正式签名、真实 ARM64 验收、八台 UI 分片以及功能硬门槛保持。四个 UI 证据汇总保留并行，不将并行处理强制串行化；后续以真实作业耗时、传输量和设备证据验证收益，再决定是否合并。

### 对照 777 的统一构建与设备验收

- 以 777 的 `android-capability-contract.yml` 为参考，计划完成后并行执行静态审计、脚本预检及 Kotlin 编译/单测/Lint；编译不再等待无直接输入依赖的两个检查。最终 `111 合并验收` 仍核对全部适用结果。昂贵原生构建保留预检依赖以避免错误候选消耗资源。
- UI APK 与测试 APK 仍只构建一次，八台模拟器共享经校验的同一原始产物；ARM64 手机完整包、x86_64 真核心包及正式签名包因运行时和签名不同保持独立。Gradle Wrapper 的固定哈希校验集中在 CI Android 环境入口，位于 Gradle 初始化前，五处编译入口统一使用。
- ARM64 Debug、x86_64 真内核、ARM64 Release 共用 `.github/scripts/assemble-product-runtime.sh`，按 ABI 直接获取原始运行时产物、校验清单并装配原生核心，保持各自的后续 APK 构建、增量更新、签名与验收不变。用户工具链独立交付，CI 仍使用 Runner 官方环境。
- 777 的发布和设备档位、工具链定时刷新与归档删除策略不直接移植；111 保留现行 API 37 八分片、x86 实核、ARM64 正式签名实机门禁与现有保留策略。实际端到端时间和 Runner 用量以本候选通过后的运行数据为准。

## 非产品变更快速检查（现行规则）

纯文档、CI 配置/脚本、工作流、Action、测试及诊断工具、用户工具链的改动只执行统一分类、基础语法/脚本回归检查及合并状态汇总；不自动启动 Kotlin/Android 构建、V8/Rust、模拟器、APK、签名或发布。`scope.json` 统一登记非产品路径；与产品代码、实际产品运行时或未知路径混合时保留完整验收。手动全量入口继续有效。轻量检查生成的凭证不具有产品发布资格；发布端继续核实真实完整产品凭证，纯维护差异不产生新 APK。历史凭证复用仍依据实际输入及消费者影响独立判断，不能把轻量检查当作产品通过。


## 显式主线切换

仅当 main 推送的提交标题以「主线强制切换新版」开头时，统一 CI 强制全量验收当前提交，并由现有队列收敛工作流取消切换前创建的本仓旧版统一验收（含已丢失 PR 关联信息的运行）。保留同一目标提交、新创建运行、独立工具链及正式发布工作流；清退前确认目标仍为 main。普通文档、CI 和工作流提交仍只执行基础检查。手动清退入口支持预览；实际发布仍需同提交完整验收与 ARM64 真机门禁。

### Actions 运行环境

仓库根目录 `.github/workflows/` 与 `.github/actions/`（含独立用户工具链工作流）使用原生 Node.js 24 的官方 Actions 版本，均固定完整提交 SHA；不修改上游镜像自带的工作流。checkout、cache、upload-artifact、download-artifact、setup-java 和 setup-gradle 统一升级，Java 编译问题注释显式保留。Gradle 保留官方默认的增强缓存，产物仍使用默认 ZIP 格式，既有名称、ID、摘要和发布门禁不变。专用 ARM64 自托管发布 Runner 必须满足 Node.js 24 Actions 的最低版本 2.327.1（如在 Docker 容器内使用 checkout 持久化凭证则至少 2.329.0），实际设备仍需通过原有发布验收。日常依赖维护仍按非产品变更基础检查执行，不新增定时任务。
