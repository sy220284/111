## 一、核心结论：不是全是空登记，但也远非全部已用起来

**多数功能已存在实际代码、函数处理逻辑和调用约束，不能简单说“只是登记”。** 例如：`TaskUpdate` 有状态/owner/blocks 更新和消息派发；`CronCreate` 有真正注册操作、时间运算和持久化选项；`PushNotification` 会根据开关、用户是否在线及传输渠道决定发送，并返回精确失败原因；`SendUserFile` 读取/审核文件后调用上传并返回附件结果；`Projects` 携带访问令牌执行项目方法；`rewindFiles` 会判断历史快照、计算差异和执行恢复。

**但这些多是原 2.1.310 恢复包里已经存在的混淆业务逻辑，不等于最近新增实现。** GitHub 路径历史显示 `core/chunk-fmtkn1kz.js`（Cron）、`core/chunk-pp7zwndm.js`（工具池/任务）、`core/chunk-5q1fx7z3.js`（通知）、`core/chunk-3827ysmv.js`（回退）目前仅查到 2026-10-28 `faed746555` 的路径归集提交；**没有提交差异证明这些函数是该次工作中新补写的业务语义**。反之，[Linux 独立进程后端](../../runtime/linux/process-transport.mjs) 有明确移植提交 `3d03a0bf90`，但不代表它被接入默认 CLI。

### 四种证据不能混为一谈

1. **名称或文档登记**：出现工具、命令或技能名，只能说明设计入口。
2. **非空函数语义**：有真正的 `async call`、输入校验、存储、状态与错误分支，说明实现并非占位。
3. **用户主入口接线**：注册到 `getAllBaseTools/assembleToolPool` 或命令分派；还要注意开关、宿主和凭据条件。
4. **真实行为验收**：实际 CLI/Worker/MCP 子进程、真实文件与协议走通；**本地模拟模型不是云端认证，独立测试不是默认界面已集成**。

## 二、实现度定义

这里的百分比是**证据完成档位**，不是函数数量覆盖率，也不是臆测的代码完成百分比。一项功能即使拥有完整内部算法，只要默认入口/端到端未验，也不能计 100%。

| 级别 | 实现度 | 判定 |
|---|---:|---|
| L0 | 0% | 未找到充分生产实现证据；不等同已证明完全缺代码 |
| L1 | 25% | 有独立实现、局部运行或资源，但默认使用链路尚未证明 |
| L2 | 50% | 有真实业务函数且存在 CLI/工具入口或调用分支；全链未完成端到端验证 |
| L3 | 75% | 真实 CLI/进程在受控环境下跑通该场景；非真实线上全边界 |
| L4 | 100% | 真实用户/在线服务/设备、含关键失败边界的完整验收 |
 
**L2** 仍可能有 feature flag、用户授权和服务依赖；**L3** 只覆盖真实测试明确执行的受控场景；独立组件即使测试通过，未接入默认 CLI 仍标 **L1**；本轮不把任何条目标为 **L4**。
