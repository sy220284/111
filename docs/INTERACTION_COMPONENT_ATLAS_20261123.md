# 111 安卓交互组件图谱与替换规则（2026-11-23）

## 目标与参考范围

基于十张交互设计图谱，将其信息架构和可复用交互提炼到 **111 原有 Ink 典雅白体系**。矢量图谱放在 [ui-assets/interaction-atlas-mobile.svg](ui-assets/interaction-atlas-mobile.svg)，使用与 `VisualSystem.kt` 相同的语义颜色，SVG 的图形和文字可单独编辑。

本次重点解决“点击更多以后在当前条目下方插入一大片内容”的不稳定体验：条目之间会被推开，用户失去操作位置，重复关闭困难。统一用可关闭、可滚动的底部面板承接详情和次级操作。列表继续显示名称、状态与必要动作，更新进度仍在列表原位。

## 十张参考的业务适配

| 参考主题 | 111 对应使用场景 | 采用方式 |
| --- | --- | --- |
| AI 聊天输入 | 对话输入、附件、指令、发送、流式反馈 | 继续复用现有 `ConversationComposer`，保留正在执行时的输入与停止 |
| 媒体播放与手势 | 语音输入反馈、长时任务进度的交互原则 | 仅保留图谱素材与“真实进度、可中止”的原则，未添加无业务来源的播放器 |
| 新手引导、轮播、分页 | 未来上手指引和有顺序的任务步骤 | 图谱为原始矢量素材；当前产品保持任务优先，不新增无效引导页 |
| 表单、选择与筛选 | 项目新建、配置项、会话分组与搜索 | 表单改在独立面板填写；筛选条件继续直接可见 |
| 加载、骨架与进度 | 等待服务商能力或会话详情 | 新增 `CodexSkeletonRows`，等待真实响应时显示稳定占位 |
| Toast、Snackbar 与系统提示 | 成功、风险、失败、重试 | 保留 `CodexNotice` 和真实反馈源，结果在原流程内展示 |
| 底部弹窗与多级高度 | 查看详情、编辑、次级选项 | 新增 `CodexDetailSheet`，支持拖动、关闭、内容滚动和软键盘避让 |
| 长按菜单、上下文菜单、手势反馈 | 文件和会话“更多”菜单 | 新增 `CodexActionSheet`，完整保留原操作与危险确认 |
| 各类弹窗与模态框 | 已有底部面板里的简短会话信息 | 新增 `CodexInfoDialog`，避免在同一位置叠两层底部面板 |
| 基础按钮、状态与组件库 | 全局设计基础 | 复用 `VisualSystem.kt` 和 Material 3；保留无障碍、深色和系统字号支持 |

## 新增共享组件

- `CodexDetailSheet.kt`：`CodexDetailSheet`（说明/编辑详情）、`CodexDetailTrigger`（统一入口）、`CodexActionSheet`（文件/会话菜单）、`CodexInfoDialog`（弹层内信息）、`CodexSkeletonRows`（异步骨架）。
- 所有底部面板都有明确标题和 48dp 关闭按钮，支持从半屏拖动到全屏，长文本可滚动。打开和关闭只改变面板，不改变原列表尺寸。
- 操作菜单由业务页面传入回调；菜单只负责承载和关闭，原 `ViewModel`、本地文件管理、安全确认、运行状态与错误处理均保持同一入口。
- 操作后保留对原始页面的返回路径。执行中要在原位显示实际进度或占用状态，隐藏弹层后仍可重新打开检查和取消。

## 已迁移页面与验收目标

| 位置 | 新交互 | 核对点 |
| --- | --- | --- |
| 服务信息、诊断结果 | 详情底部面板 | 原列表不移动；可关闭；描述、状态完整 |
| 自定义服务商 | 底部编辑面板 | 原字段验证、保存确认和异步回读保留 |
| 服务商能力 | 详情面板与骨架占位 | 只在点击时刷新真实能力；失败可见 |
| 启动日志、崩溃记录、连接排查 | 独立面板 | 长文本可滚动；清除记录需保持原操作 |
| 高级配置 | 独立底部编辑面板 | 原键名/类型校验及二次确认仍生效 |
| 工作区新建 | 独立底部编辑面板 | 保留文件/文件夹切换、名称校验、刷新目录 |
| 工作区文件更多菜单 | 上下文操作面板 | 重命名、复制、删除和后续确认完整保留 |
| 会话列表更多菜单 | 上下文操作面板 | 重命名、归档/恢复、移至分组、永久删除 |
| 会话工具中的“会话信息” | 简短信息对话框 | 同一底部面板里查看信息，不再推开其他工具 |
| 应用更新卡 | 卡片实时状态 + 更新底部面板 | 下载进度和失败仍在卡片；操作在面板中 |

权限档位选择应当直接展示全部可选项，因其本身就是当页核心任务；Diff 的逐文件展开是代码阅读方式；任务预算等直接参与当前表单计算的字段仍采用原位编辑。二者应与被动详情的“查看更多”区分，避免额外步骤。

## 使用约束与验收

1. 新增详情入口时优先用 `CodexDetailTrigger` + `CodexDetailSheet`；页面里已经有底部面板，简短二级信息使用 `CodexInfoDialog`。多选筛选仍优先保留可视选择结果。
2. 文件、会话、任务相关的二级操作优先使用 `CodexActionSheet`；具有副作用的操作保持原确认、审批和后台回执逻辑。
3. 浅色/深色、触控不小于 48dp、TalkBack、减少动效和系统键盘沿用 `AGENTS.md` 与 `docs/DESIGN_SYSTEM.md` 的既有硬性要求。
4. Android 仪器测试 `CodexInteractionComponentsInstrumentedTest` 覆盖面板显示、关闭、原列表保留及操作执行；`UiNavigationInstrumentedTest` 覆盖页面内完整路径。验收须以实际 CI、Android 35 的 360/393/411dp 截图为证据。
5. 当前 Figma 目标文件为 `K4FEMoNdmQbcnJZCHWr8c7`；Starter MCP 配额限制了画板写入。图谱 SVG 可直接导入作可编辑矢量参考，后续 Figma 同步仍以实际文件节点与截图验收，不用代码提交代替设计落地。

## 避免重复建设

此文件是 `AGENTS.md` 的实施细则，长期唯一规则仍写在 `AGENTS.md`。新模块直接复用已有共享组件和矢量素材，减少另起一套“更多按钮—展开块”的代码。接口方向与可用性继续由 `docs/PROTOCOL_ACTION_IMPLEMENTATION_LEDGER_20261122.md` 及源码决定；本次仅变更呈现容器，没有修改任何 RPC 参数或接口能力。
