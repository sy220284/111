# 111 剩余审计问题闭环方案

基线：PR #113，5427359。目标是保持完整本地开发、项目迁移与任务能力，同时用可执行的验收证据代替风险说明。

## 1. 数据迁移（P0）
- 统一真实存储命名规则；按内容寻址校验快照引用、对象 SHA-256 和大小，冷启动写入前复检。保留原有 ZIP 配额、路径约束和中断回滚。
- 新增实际 AnswerWorkspaceStore 写入→归档→恢复→重新回答的设备回归，验证源工作区不变；缺失及篡改对象拒绝恢复。
- 当前格式恢复 rollout、历史索引、草稿、图片、工作区、回答快照等明确内容。SQLite 的任务目标、队列、记忆、历史等须逐表确认数据语义与官方 RPC，设计版本化逻辑导出/导入、旧 ID 和路径映射、冲突报告与重建索引。整库复制可能恢复安全状态或造成跨版本不一致，不能作为解决方案。当前明确提示遗漏，尚未实现逻辑迁移。

## 2. 真实终端隔离（P0，尚未完成）
- 目标：应用凭据/配置由可信主进程持有；本地命令默认在独立 UID 或经设备证实的系统沙箱中运行，仅访问当前授权项目与自己的工具/临时目录。PTY、子进程、Git/Python/Node/npm 保持可用。
- 已增加 Debug 专用固定探测服务和设备回归，验证独立 UID、应用私有文件拒绝读写、未授权网络拒绝，并记录文件描述符及原生 shell 是否可用。先在 API 29/35/37 ARM64 上取得实际 native exec、文件描述符和 SELinux 证据。独立 UID 工作者不能继承主应用所有文件权限；通过 Binder 或签名认证的伴生执行器传输项目数据，实施事务同步、根路径校验和冲突回执；网络默认拒绝，联网经明确授权并通过受控网络通道。若 isolatedProcess 不支持任意本地原生进程，选择独立包 UID 或远端隔离执行器，避免用同 UID 子进程伪装隔离。
- 统一 agent shell/process、交互式终端、MCP 工具、固定探测入口及后台任务的执行授权；所有子进程继承边界。对明确选择的全权限本地模式保留当前能力与真实说明，不允许静默降级。
- 验收：工作区读写成功；其他项目、应用私有配置、凭据、共享存储非授权目录均实际拒绝；网络关闭时 TCP/UDP/DNS 被拒绝，授权网络正常；符号链接、子进程、PTY 后续输入、断线与终止均测试；非通过设备不得显示受限模式可用。当前 externalSandbox 仍无 OS 文件边界。

## 3. 可信构建（P1）
- 固定官方 V8 源码、锁文件、NDK 和官方签名仓库；禁用原始 V8 缓存跨构建复用，完整原生核心依靠主线已验收的精确输入指纹复用。验证构建凭证和两 ABI ELF 及 V8 self-test。
- Gradle 基线通过真实 Debug、Release、JUnit、设备测试 APK 和 Lint 任务图生成，审核实际 lockfile 和 verification-metadata 后提交，严格验证依赖完整性；禁止发布未审查基线。候选基线生成通过前保留草稿。统一合并验收及正式签名发布均已增加基线存在性拦截，正式构建强制严格验证。
- GitHub main 应配置要求 PR、要求最新基线及唯一必需检查“111 合并验收”，关闭直接推送、强推和删除，管理员同样遵守。连接器无分支规则写接口，需管理员在 Settings→Rules→Rulesets 设置并回读验证。

## 4. 隐私、性能和维护（P1/P2）
- 语音：核验 Android/Rust 全路径日志、退出清理、转录保留、实际端点；服务端保留政策需按实际账号和服务核验。
- R8：生成独立签名候选及映射、体积对比；真实 ARM64 包验证 29 页、JNI、全部 RPC、终端、安装升级、备份、联网后才更改发布默认。当前不把压缩编译当成真机通过。
- ViewModel：提取通用请求控制器，保留唯一请求租约、配置世代、响应归属及反馈；后续按对话发送、登录、任务生命周期继续拆分，以现有协议和交互回归为约束。

## 5. 统一整合验收
- #110、#112、#113 共享工作流和验收脚本。按基线和差异逐个语义合并，保持唯一构建调度规则和固定 Action SHA；不能只选一侧文件。每次基线变化重新核对最终实际提交。
- 验收证据：统一 CI 全通过、两 ABI 原生构建/复用凭证、设备回归、正式签名 ARM64 安装、真实账号网络及权限测试、依赖锁审查、主分支规则回读。没有证据的事项保持未完成。
