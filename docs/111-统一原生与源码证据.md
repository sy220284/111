# 111 同提交原生与源码分析证据

运行 `.github/workflows/integrated-reverse-evidence.yml` 将当前提交的 AST 全量调用图、仓库中两份真实 `.node` 二进制的 Ghidra 反编译结果及来源 SHA256 放进同一个 Artifact。

工作流复用 `111 开发工具链` 中已经通过验收的 JDK25/Ghidra12.2 离线组件。默认来源是主分支 run `40678086652`，也可以通过 workflow_dispatch 指定别的已验证工具链运行。此运行号**只是工具来源**，源代码和原生二进制均从本次 checkout 同一提交获取，绝不会把旧的源代码分析当作本次结果。

输出 `source-graph.json`、`integrated-evidence.json`、`audio-capture.node/{decompiled.c,functions.tsv,summary.json,input.sha256,ghidra.log}`、`clipboard-napi.node/...`。每个函数成功/失败均逐行校验，每个输入二进制哈希与本次仓库实际字节核对；失败不能伪装成成功。

**边界：**这只是原生和 JS 的**证据汇总**，并未建立 JS→原生地址的可靠调用边，不能恢复 JSC 字节码，不是原版主 ELF 反编译，也不能宣称业务语义或原版行为等价。完整原版 ELF 需作为独立可校验输入再接入，不能从当前仓库中凭空生成。

本工作流不替代原有的 `clean-decompile-delivery` 和 `full-reverse-archive`。后者目前固定历史 run，因此不是本次提交的自动闭环汇总；只有确认输入 SHA、运行成功和真实工件之后才应合并最终归档。
