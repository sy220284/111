> 核查日期：2026-11-23。核查范围：仓库全部 64 条 PR（#1–#65，#4 不存在）、PR 描述、主要改动文件、现行设计系统、协议归属及 100 项验收台账。当前统计：55 条已合并、6 条已关闭未合并、#63/#64/#65 开放。本文记录历史与可复用规则，**实时执行以最新 main 源码、现行协议策略及同一提交的验收结果为准**。

## 1. 现在生效的产品基线

1. **任务对象为中心**：项目 → 会话 → 执行/审批 → 文件、终端、Diff、审查；手机以顶部导航和抽屉侧栏承载常用入口，≥720dp 常驻侧栏。无底部五槽导航。长期配置在设置，任务操作在当前任务附近。
2. **组件按工作量选型**：长时间阅读/编辑用完整 Page；当前任务的搜索、目标、队列、模型、审批用 Sheet 或上下文操作；危险删除、权限扩大、覆盖用 Dialog；长期配置在设置；纯后台方法无需用户页面。
3. **后台与用户语言分离**：用户看任务目标、状态、后果和恢复动作。普通界面隐藏 RPC 名称、null、UUID、私有绝对路径、原始 JSON 与实验内部代号；真实诊断按需展开。
4. **功能闭环**：入口 → 参数与权限 → 真实请求/本机等效实现 → 有效响应与事件 → 进度、结果、错误 → 可继续或恢复；点击有效、接口名存在、静态字符串命中均只是局部证据。
5. **协议一份来源**：`android-app/tools/ui_surface_policy.json` 为官方请求 UI 归属单一来源，生成 Kotlin `UiProtocolMatrix.kt` 和映射文档。锁定版本的 195 项为直接 38 / 上下文 43 / 高级 52 / 后台 60 / Android 不适用 2。官方 Rust DTO、Host 方向、请求/响应字段与通知独立验证；若上游方法数量变化，重新提取，不硬编码旧数量。
6. **任务状态隔离**：按 threadId 区分活动回合、消息、草稿、附件、队列、任务状态和反馈。多会话可同时执行，同一会话防重复提交；切换必须先恢复真实会话；失败与未知结果保护用户草稿。
7. **真实数据优先**：草稿和未发送图片保持本地持久化；断线、失败、超时、后台执行与系统重启有明确处理。未经服务端成功确认不能清除输入或宣称完成。
8. **视觉当前基线**：典雅白、语义化珊瑚主操作色，白底轻描边和适度留白；深色主题使用同名语义 token；48dp 触控、对比度、字体放大、键盘与安全区、减弱动效均属于验收范围。以 `docs/DESIGN_SYSTEM.md` 与 `VisualSystem.kt` 的当前一致内容为准。
9. **交付基线**：正式手机包 ARM64，x86_64 主要用于 Android 35 模拟器 UI/交互验收；360/393/411dp 三种屏宽截图必须来自已就绪的真实页面。发布通过实际作业和 SHA、APK 结构、签名、版本与系统安装路径验收。厂商真机问题需对应厂商实测。
10. **未启用或尚待验收的功能**：与已实现、专项通过、真机验证分别列账，实验/Host-only/平台不适用接口按实际能力决定入口。保留现有本地存储与用户自行选择的远端执行方式。

## 4. 其他模块需要推广检查的范围

每次修复先识别**共因**：同一种错误是否存在于共享组件、同类业务的其他入口、后台状态、历史恢复、测试或发布链。每个模块记录“已复用 / 有差距 / 待专项验收 / 不适用”和对应 PR、文件及截图证据。

| 优先级 | 模块 | 必须横向检查的体验及根因 | 主要审计入口 |
|---|---|---|---|

## 5. 固定执行流程：下次不再从零分析

**输入**：用户目标、新问题、截图或想优化的模块。

1. **找入口**：以 `UiFeatureCatalog`、导航策略、`ui_surface_policy.json`、现行设计和历史 PR 索引找同一用户操作的所有入口；记录已合并、待合并和关闭替代关系。
2. **找根因**：把问题从单页扩展到共享组件/共享状态/参数协议/测试与构建。列清现状、要达到的体验、根因及可能受影响的同类模块。
3. **定改法**：优先采用一套共享策略/组件/状态模型或单一数据来源，保留真实业务能力；新入口有明确用户需要才加入。视觉、文案、交互和功能链在同一次改造中收敛。
4. **查旧成果**：对比 PR 列表和历史台账，直接复用已验证逻辑；以最新 main 为起点。开放 PR 相交时逐文件核对，不把同一改动重复实施。
5. **实施与横向推广**：每修一种错误，顺带扫描同类页面、一级/二级/三级子页、按钮、Sheet、Dialog、宽屏、后台事件和恢复路径，列明适用与不适用理由。
6. **验收**：代码静态检查、契约/单元、Lint、360/393/411dp 的 UI 行为与真实截图、APK/原生专项、必要厂商真机；核对实际显示文本、成功和失败/重试。每一项标记证据级别。
7. **回写**：更新本 PR 行、受影响模块、历史规则替代关系、100 项原编号状态、证据 SHA/Actions 链接与未来复用原则；PR 标题和描述中文；保留所有原功能的可达性。
8. **交付报告**：明确修改前问题、根因、共享修复位置、实际变化、横向覆盖范围、验证结果、尚待真实环境验证的事项；不以提交成功充当完整交付。
