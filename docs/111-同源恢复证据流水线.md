# 111 同源恢复证据流水线

入口：.github/workflows/recovery-evidence.yml（手动触发，或该工作流及验证脚本修改时在 PR、main 自动触发）。

目标：固定到**同一 Git 提交**的源码调用图、Jelly 静态候选、真实原生插件反编译以及 CLI 本地业务回归，做跨阶段验收，不宣称原版 ELF、JSC 或业务等价已恢复。

三个作业：

1. source：锁定 Node/npm；重建 2,551 个主模块函数索引与完整 AST 调用图，生成闭环报告；锁定 Jelly 0.13.0，对两个真实模块进行有边界的静态指向分析；运行 CLI 本地模型 SSE/MCP 工具回环测试。全量 8 分片 Jelly 仍由 clean-decompile-delivery 单独负责，本流程的两个模块样本不是全量 Jelly 结果。
2. native：用官方 SHA256 校验的 Ghidra 12.2 和 Temurin JDK 25 对仓库真实 audio-capture.node 与 clipboard-napi.node 进行反编译，按每函数保留 C 伪代码、成功失败结果、日志、原件 SHA256；不再只分析临时编译的测试 ELF。
3. integrate：仅下载**本次工作流**的 source/native 产物，交叉检验提交 SHA、Jelly 输入 SHA、原生插件 SHA256、Ghidra 函数计数与逐行状态。一旦不一致，就阻断最终产物。结果名为 111-same-commit-source-native-recovery-evidence，包含 source/、native/、SUMMARY.json、SHA256SUMS。

本地复验（需本次运行的两份 stage 证据）：

    python3 -m unittest discover -s tests -p 'test_recovery_bundle.py' -v
    python3 tools/analysis/recovery-bundle.py --root . --source /path/to/source --native /path/to/native --output /path/to/empty-output
    (cd /path/to/empty-output && sha256sum -c SHA256SUMS)

**边界**：未包含原版 Claude 主 ELF，未将 JSC 字节码转成源码，未证明跨语言映射或原版行为等价。旧 full-reverse-archive 工作流仍下载固定历史运行号，是研究成果归档；不能冒充本轮同源验证。要纳入用户的原版发行包，必须先增加可追溯的原件导入与来源哈希检验，并实现专用 JSC 解析及原版差分。

旧 dev-toolchain.yml 保留离线 Node、Bun、Jelly、Ghidra、JDK 组件发布与专项验收。本流程采用与清单相同的固定版本和 Ghidra 官方哈希，但直接下载官方 Ghidra，以避免单一 Artifact 大文件下载限制影响真实原生模块分析；它不是对原有离线工具链的替代。分卷工具链修复属于独立 PR #59。
