**对照对象**：DSH Go `ccch1mneyyy/dsh-Go` 正式发布 `v1.3.0`、官方 Flutter/Android 源码与设计规范；111 `sy220284/111` 主分支（合并 PR #55 和 PR #58 后，提交 `290e4ea47eecec3217f278eca278c8510263e498`），以及 Android 35 三种屏宽的真实设备测试截图。

## 0. 方法、实测边界与最终结论

**二进制已核实**：DSH Go v1.3.0 官方 `dsh-go-1.3.0-arm64.apk`（239,344,269 字节），GitHub Release 资产 SHA-256 为 `f818371f4ebf63c8b42c5a8275b2618b75852dbf4078e2959e9c8294b7658a9f`。GitHub Actions 从官方发布页下载、校验 `SHA256SUMS`，在隔离的 Android 35 模拟器安装并成功启动，保存欢迎页截图和 UI 层级。用户资料库此前未找到同名 APK；现已把官方发布文件通过四个校验分片完整重组到本地，实测 239,344,269 字节，SHA-256 与官方一致。APK 内含 739 个 ZIP 条目和 21 个 arm64 原生库文件，Flutter UI 实现仍以对应源码为准。

**实际操作覆盖**：已在 Android 35 模拟器完成欢迎页 → 运行方式选择 → 远程主机选择 → 远程连接配置的真实点击路径，保存每屏截图、Accessibility XML、控件坐标及动作摘要。欢迎页的“发送匿名使用统计”默认开启，测试流程主动关闭再继续。远程配置屏可看到扫码配对、GitHub/Google/知乎/QQ 登录以及自建服务器邮箱登录入口；测试未输入账户凭据或连接真实主机。设置、终端、插件、手机操控等非已到达的功能页面仍以官方 Flutter 源码及测试 Goldens 为证据，不能当作逐屏实际点按的结果。

**111 当前成果**：PR #55 已整合工作区、会话与任务结构，PR #58 已将附件选择与工作区工具分离、完善设置搜索同义词、校准会话工具定位和设备测试，并以中文提交合并到 `main`。最终 PR #58 的分支测试通过 Kotlin 编译、协议校验、Lint 和 Android 35 360dp / 393dp / 411dp，每种尺寸 55 项 UI 仪器测试，截图清单完整。合并后的主分支提交和 11 个目标文件已二次核对。

**总判断**：111 的功能归属已经建立“常驻工作区 / 会话操作 / 设置配置”三层，和 DSH Go 的交互原则一致；目前有明确的改进成效。剩余值得继续优化的重点为全局连接错误与局部错误统一反馈、空弹层高度、空页面说明密度，以及设置项级别的精确跳转。这些属于后续视觉和交互质量提升，需按实际用户任务的端到端路径验收。

## 1. 两套产品的可比范围

DSH Go 是 Flutter 安卓原生外壳+本地运行环境或远程宿主，包含手机操控、插件、终端、远程主机、宠物、语音、酒馆等很多额外功能。111 是 Codex App Server 的安卓工作端，目标是 AI 编码任务和 Codex 上游接口。**只比较相同用户任务的入口、反馈和界面职责**；DSH Go 的手机特权通道、宠物与酒馆属于其独有业务，不能按“缺了 DSH 功能”认定 111 UI 错误。

DSH Go 官方页面骨架：枢纽页（设置/全部功能）、详情页（引擎/插件）、列表页（会话/技能/插件）、表单页（服务商/授权信息）、弹层（模型/确认/切换）。实际源码可核查 `HomeShell`／`SessionsDrawer`、`SettingsScreen`／`SettingsSearchIndex`、`showAppSheet`、`Composer`、`PhoneControlScreen` 等组件；对应设计文档 `docs/design/page-design.md`、`docs/design/settings-ia.md`、`docs/design/onboarding-parallel-setup.md`。

111 已将 29 条主功能路由登记到 `UiFeatureCatalog.kt`，并以 `UiProtocolMatrix.kt` 记录接口曝光等级，覆盖实际的会话、任务、文件、模型、服务商、审批、终端、插件和设置 RPC。各页应以这些共享策略为依据；单纯“有页面、有按钮”不能证明 API 调用及反馈完成。

## 4. 建议的整体优化方案（以可复用为主）

**第一层：统一入口与信息结构。** 保留 111 已建立的主工作区、上下文任务弹层、设置管理页三层；给每个功能建立唯一的 `用户想做的动作 -> 所属任务上下文 -> UI 容器 -> 实际 RPC -> 成功/失败/恢复` 映射。尤其将“附件添加”“任务工具”“全局设置”从触发点上分开，让任何入口打开的都是同一套最终组件。按用户任务命名可见标题。

**第二层：统一页面状态和反馈。** 设计公共状态组件：加载、空白、未连接、无权限、功能不可用、保存失败、处理中、已成功，状态由真实连接与 RPC 结果决定。全局断连提示与页面局部问题去重，失败可在原操作处重试；不能发送的按钮明确原因，重连后恢复用户草稿。关键敏感操作要求准确反馈、明确确认和结果回读。

**第三层：交互组件。** 借鉴 DSH Go 的自适应 Sheet 规则：短内容弹层按内容高，长列表扩展为大弹层，编辑未保存时关闭要确认，系统键盘/横屏/大字号正常。设置搜索使用同源索引、别名、路径、目标行聚焦；服务商配置的保存按钮固定在底部，字段错误写在字段旁。把技术说明移到“高级信息/诊断日志”，使运行状态和真正操作成为第一视觉层级。

**第四层：可持续验证。** 不只按页面截图验收，要用 29 条 `UiFeatureCatalog` 和对应 RPC 矩阵自动生成：入口可达性、调用参数、加载/成功/失败、无会话续接、取消、返回、重进状态以及 360/393/411dp 的截图清单。目标是一次建立共性标准，今后新增功能自动纳入同一验收机制。最新 CI 完成后需验证 PR #55 **最新 SHA**，包括真机升级后的恢复/权限流程。

## 7. 固定复现路线

`GitHub Actions → DSH Go 安卓安装与界面参考验收` 通过官方发布的 APK 与 `SHA256SUMS` 进行校验，再由 `android-app/tools/capture_dsh_onboarding.py` 在 Android 35 模拟器记录页面：欢迎 → 关闭使用统计 → 运行环境选择 → 远程主机 → 配对配置。每一步都保存图片及控件树；APK 超过 100 MB 时用 SHA-256 校验的 70 MiB 分片下载后重组，同一个功能变更后可重复核实。完整界面与业务接口差异依靠 `UiFeatureCatalog.kt`、`UiProtocolMatrix.kt` 及多屏设备测试固定验收。
