# 发布后整机压力测试（独立观察项目）

仅在正式版本已发布之后，使用专用 ARM64 实机手动执行。常规 UI 交互、构建、合并、发布门禁不调用本专项，也不等待其结果。低于指标、测试中断、设备缺失、充电或计数器不支持都如实记录。

## 测试规格

| 指标 | 默认规格 |
|---|---|
| 历史消息 | 5000 条 |
| 单轮流式正文 | 500000 UTF-16 单元，达到上限后开启下一轮 |
| 持续时间 | 1800 秒 |
| 更新频率 | 100 次/秒 |
| 负载达成率 | 90% 参考线，仅记录实际达成情况 |
| 帧率 | 实际窗口帧时间戳、P95、掉帧采样 |
| 内存 | PSS、原生及托管内存 |
| CPU | 被测应用进程 CPU 耗时 |
| 功耗 | 未充电时整机能量计数器，或电荷及电压估算；不支持时留空 |

## 执行方法

在专用测试设备上安装已经正式发布的单一 ARM64 APK（勿使用个人业务设备）。准备与该发布版本相同源代码的 Android instrumentation 测试 APK；正式应用及测试 APK 需要同签名，Android 会核验测试进程的签名权限。可以使用发布源码构建的 `assembleDebugAndroidTest` 产物，由持有发布签名权限的操作者在本地重新签名；当前正式版默认未启用 R8，若未来启用混淆，须使用对应构建变体及映射编译测试 APK。签名密钥不进入仓库或报告。

```bash
python3 android-app/tools/run_post_release_pressure.py \
  --physical-serial <ADB设备序列号> \
  --released-apk <已经发布的APK> \
  --test-apk <同源同签名测试APK> \
  --output ./post-release-performance
```

脚本核对设备安装 APK 的 SHA-256，仅安装测试 APK，不覆盖正式应用。建议使用无线 ADB 并断开充电线；功耗为整机测量，不能归因给单一应用。测试使用应用真实 UI 与模拟流式数据，未包含真实服务网络或原生核心通知吞吐。CPU 为应用进程指标。

每次执行生成唯一目录，保存 `result.json`、原始 `instrumentation.log`、`measurements.json`（取得时）。报告中所有参考线只供比较；不达标、缺失或无法运行均不阻塞发布。专项报告不参与 CI 或发布门禁，不创建定时任务。
