## 1. 统计口径与结论

| 检查对象 | 数量 | 实际含义 |
|---|---:|---|
| 一级侧栏功能入口 | 28/28 | 四个分组、28 个页面路由都有对应 Compose 页面 |
| 主功能分组 | 4/4 | 工作台 6、开发工具 4、Codex 生态 8、偏好与设置 10 |
| 官方 app-server 请求方法 | 192 | 仓库锁定的 Rust 官方请求分发表，包含平台、实验及非移动 UI 能力 |
| Android 源码引用的官方请求方法 | 约 57 | 直接在 Kotlin 字符串常量中引用的不同方法数；不把协议事件通知算成主动请求 |
| 新增原生 UI 能力 | 4 类 | 会话资料库、分支/上下文工具、运行中追加指令、使用量/限额展示 |
| 关键已通过的旧版模拟器测试 | 9 项独立 UI、12 项原生核心 | PR #10 合入时的事实；新 PR 的结果以本分支 Actions 为准 |

`57/192` 是**请求方法引用率**，不等于 111 的核心功能完成率。即便 Android 应用完全成熟，也不需要为 Windows Sandbox、设备外远程控制、维护协议、内部反馈等全部 192 项接口设计独立界面。页面完成、操作有真实请求、设备端成功三个层次分别统计。

使用的四项资料库技能及适配方式：

1. **UI设计技能 / finesse-ui**：采用产品型工作台的高密度内容层次，图表、指标、筛选、空白态与错误态都以真实数据为准。
2. **工作台架构师 / finesse-brief**：继续保留四个一级分组，复杂任务通过列表—操作—详情三层到达；将会话管理从底层协议上提为自然的手机操作。
3. **视频审美动效 / frame-smith**：提炼“只在动作有意义时运动”和节奏一致性，沿用 `CodexMotion` 与系统减少动画设置；视频剪辑/Remotion/音轨不进入原生 Android。
4. **术语技能 / finesse-term**：以“已归档、恢复会话、补充指令、查看原始数据”等面向用户的同一称谓表达；协议 method 保留英文精确名称。

图形素材沿用仓库已有 Material Icons Extended 矢量图标，按“任务、归档、分支、压缩、额度”语义选用；无外部图片加载、无额外网络资源依赖。新组件复用 `Ink` 石墨暖铜色、`MaterialPanel`、`SectionIntro`、`CodexNotice`、`CodexEmptyState`、`CodexReveal`、`CodexConfirmDialog`，保持布局体系一致。

## 4. 当前未完成与后续改进方向

以下是**有实际用户价值的功能缺口**，与“官方接口总数减去已引用接口数”分开：

1. **附件与多媒体输入**：当前任务输入主要为文本；官方输入协议支持图片/文件及实时音频能力，需要平台权限、预览、上传来源与本地隐私控制一并设计。
2. **工程级管理**：项目创建、列表、移动、删除和本地文件目录的协作关系尚待整合；当前文件页主要管理本机 `projects/`。
3. **历史 Diff 与可恢复操作**：当前差异聚焦最新任务事件，历史对比与回退需要明确文件修改风险与恢复范围。
4. **高级终端管理**：持续进程、输入流、终端大小变化未统一为会话式终端 UI。
5. **MCP 和插件深入管理**：资源阅读、插件详情/检索/更新、错误排查和服务刷新可进一步完善。
6. **账号与服务商高级配置**：多账号会话切换、认证结果、服务商自定义配置需按真实协议校验。
7. **搜索与审查结果体验**：命中片段、长列表分页、结构化审查结果定位仍可完善。
8. **设备与真实服务验收**：ARM64 真机、真实 OAuth、云端模型长任务、权限操作、MCP、TalkBack/大字体、多窗口与最终发布签名，需以端到端证据完成。

按**一级导航**计，当前缺少页面 0/28；按上述需改善的**功能簇**计还有 8 类。每类包含多个接口和跨页面交互，因此不能把“8”理解为只需画 8 张页面。PR #11 先完成最影响日常工作流、已有官方协议支持的四类新交互，剩余仍在此清单中公开列明。
