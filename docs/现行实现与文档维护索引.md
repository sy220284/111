## 5. 长期维护流程

1. 先核对目标 Git SHA、正式发行、开放候选和三份权威文件；当前设计约束与实际实现证据分开。
2. 功能、数据、权限或性能改动，更新对应架构条款、协议台账、现行使用说明、CI/发布/工具链相关文档；方法及组件数从源码或生成源核对，不再人工多处写死。
3. 历史审计与旧回执保持原始 SHA、日期、计数、原结论，标明替代或新增证据；历史资料不覆盖当前规范。生成矩阵同步生成源与生成结果，不能手改方法行。
4. 提交前核对文档链接、实际路径、工作流名称、版本及数值；PR 模板记录三个权威文件和受影响文档。工具链、真实设备或服务未通过，按实际缺口持续登记。
5. 正式发布只认同候选验收与真实签名/设备回执；文档提交、候选实现及历史测试均不构成自动验收通过。
