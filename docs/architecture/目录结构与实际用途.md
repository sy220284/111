# 111 仓库目录结构与实际用途

## 根目录源码

| 路径 | 实际内容 |
|---|---|
| `core/` | 2.1.310 主程序 2,551 个 JS 模块（包含 Hook Worker）及 CLI 源码和 vendor bundle；仍保持原始 chunk 名和调用关系 |
| `embedded/` | 24 份内嵌源码及配套配置，含运行时、浏览器工具、组件和模板 |
| `plugin-testing-kit/` | 294 份插件测试引擎与辅助模块，内部相对导入保持不变 |
| `tools/bundled/` | 54 份 Claude Test、Design Sync、评估、插件 API 等附带工具源码与辅助数据 |
| `tools/analysis/` | 静态依赖图、调用关系及反编译分析工具 |
| `tools/dev/` | Bun/JSC 参照、工具链安装与开发配置 |
| `runtime/` | Node/Bun 运行适配和资源装载 |
| `bin/` | CLI 启动入口，现引用 `core/cli.js` |

## 保真与验收

原始 BunFS 键不变，工具资产路径只更新 42 项 `resources/asset-layout.json` 目标；内嵌源码路径只更新 `resources/embedded-source-layout.json` 的 24 项路径。完整映射在 `resources/layout/relocations.json`。

用 `npm run check:repository-layout` 复核文件字节、路径唯一性、原工具来源与文档链接；`npm test` 和专项 CI 负责真实业务测试。结构整理不计入业务恢复，主程序 chunk 的语义拆分仍以实际消费者证据为准。

## 主程序从 src 到 core 的最终归集

- 原 `src/` 的 **2,553 个根层 JS 文件**直接放入 `core/`，旧的 `src/` 已移除，仓库根目录不保留 JS 源码文件。
- 独立 Hook Worker 仍在 `plugins/functionHooks/hooks-worker/hooks-worker.js`。总计 2,554 个原始源码文件，全部恢复原始 Git Blob；其中原本从根目录调整了 38 处 `./runtime/` 的模块，现归入 `core/` 后恢复原始 `../runtime/` 导入。
- 当前根目录分类包括 `core/`、`plugins/`、`embedded/`、`plugin-testing-kit/`、`tools/`、`runtime/`、`bin/`、`resources/`、`docs/`、`tests/`、`scripts/`、`.github/`。源码、依赖、工具、测试、文档及部署入口职责分开。
- 原历史 Git 路径（如 `src/chunk-*.js`）仅在固定旧版本来源证据中保留；当前工具、测试、依赖图和资源清单应指向 `core/chunk-*.js`。
- 迁移账本：`resources/layout/root-source-relocations.json`；核验：`npm run check:root-source-relocation`、`npm test`。最新运行成功记录未获得前，不能判为真实功能验收完成。
