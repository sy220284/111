# 111 仓库目录结构与实际用途

## 根目录源码

| 路径 | 实际内容 |
|---|---|
| `src/` | 2.1.310 主程序 2,551 个 JS 模块（包含 Hook Worker）及 CLI 源码和 vendor bundle；仍保持原始 chunk 名和调用关系 |
| `embedded/` | 24 份内嵌源码及配套配置，含运行时、浏览器工具、组件和模板 |
| `plugin-testing-kit/` | 294 份插件测试引擎与辅助模块，内部相对导入保持不变 |
| `tools/bundled/` | 54 份 Claude Test、Design Sync、评估、插件 API 等附带工具源码与辅助数据 |
| `tools/analysis/` | 静态依赖图、调用关系及反编译分析工具 |
| `tools/dev/` | Bun/JSC 参照、工具链安装与开发配置 |
| `runtime/` | Node/Bun 运行适配和资源装载 |
| `bin/` | CLI 启动入口，仍引用 `src/cli.js` |

## 保真与验收

原始 BunFS 键不变，工具资产路径只更新 42 项 `resources/asset-layout.json` 目标；内嵌源码路径只更新 `resources/embedded-source-layout.json` 的 24 项路径。完整映射在 `resources/layout/relocations.json`。

用 `npm run check:repository-layout` 复核文件字节、路径唯一性、原工具来源与文档链接；`npm test` 和专项 CI 负责真实业务测试。结构整理不计入业务恢复，主程序 chunk 的语义拆分仍以实际消费者证据为准。

## 2026-10-28 整合后逐目录检查

- 根目录共 17 项：11 个用途明确的目录（`.github`、`bin`、`docs`、`embedded`、`plugin-testing-kit`、`resources`、`runtime`、`scripts`、`src`、`tests`、`tools`），其余为说明、许可、配置及依赖锁文件。
- `src/` 顶层 2,553 个 JS 文件及内部 `src/plugins/functionHooks/` 工作器子树；其中主程序的 2,551 个分析模块统计包含 Worker。该 Worker 在仓库实际路径 `src/src/plugins/functionHooks/hooks-worker/hooks-worker.js`，是主程序内部源码，不属于应另建根目录的独立源码包，保留原版路径和冻结来源。
- `embedded/`、`plugin-testing-kit/` 与 `tools/bundled/` 分别归位 24、294、54 项原始源码/工具资源；`tools/analysis` 与 `tools/dev` 为项目自己使用的分析和开发工具。
- `resources/` 的 `bunfs`、`data`、`docs`、`layout`、`research`、`skills`、`templates` 各自存放原件、数据、参考文档、迁移映射、研究证据（含2.1.88数组工具对照映射）、技能和模板；根层固定名称的 JSON 是既有工具链引用入口，未为分类而破坏调用路径。
- `tests/` 存储独立测试、fixtures 和 helpers；`scripts/` 存储构建/索引/审计脚本；`.github/workflows/` 是 CI 配置；`docs/` 已按架构、规范、治理、历史、研究、恢复、状态和验收主题归档。
- 本次纠正 `tests/repository-layout.test.cjs` 对两份来源清单的过期路径引用；现在从 `resources/layout/{claude-test,design-sync}-source-layout.json` 读取，与实际目录一致。
- #2、#3、#6、#36、#47、#48 已整合至 #50 分支且在 GitHub 中合并关闭；**该状态不代表最终 CI 验收通过**。合并后实际修改的主模块必须重新计算函数索引指纹和复测 Daemon/查询链；CI Runner 可用之前保留未验收结论。
