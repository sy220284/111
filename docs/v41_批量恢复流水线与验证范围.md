# v41：跨版本函数批量恢复流水线（首轮实施与验收边界）

## 基准与证据

- 主程序唯一代码基线：111 仓库 Claude Code **2.1.310**，本轮从 `main@bdb5d0c255d184177aba37fe42c96e182a5af5c9` 派生，保留全部新版实现。
- 历史源码参照：资料库 `claude-code-2.1.88-main.zip`（第三方还原，`source/src/` 提供 TS/TSX）；历史版本包（含 2.1.169、2.1.197、2.1.300 对照研究）。
- 最新独立研究：v40 的 `v40_P0_92条标识符真实归属.json` 与 `v40_对111可提交研究成果评估_20261027.md`。其中 92 项所谓“未匹配标识符”均已找到真实归属，不能当作缺失函数补写。
- 研究档案中的 624 组跨版本函数匹配为**候选**，与 111 已登记的131项可读函数和173项定向验证不是同一口径。
- v40完整压缩包暂未在资料库检索到可读取的本体，已有研究证据可参考，但不能假称对该完整压缩包重新逐文件验收。

## 本轮实际实现

新增 `scripts/batch-restoration-candidates.cjs`：只读解析旧版 TS/TSX 和新版 JS，抽取具名函数体、标准化语法 token、长字符串常量及函数规模，通过唯一结构指纹和有限字面量相似度寻找候选。

- **高置信**：至少55个语法 token，旧版具名函数长度不少于4字符，而且结构指纹在旧版唯一匹配。只表示结构候选，不表示跨版本行为等价。
- **待复核**：至少两个长字符串常量一致，字符串集合相似与函数规模达到阈值，且第一、第二候选有足够分差。需要进一步核对新版调用方、状态流与错误/权限分支。
- **歧义**：多个候选接近或结构重复，不自动定名；无法定位的函数不虚报为缺失。
- 通过 `restored-symbol-aliases.json` 排除已恢复的短符号，避免重复劳动。
- 新增 `resources/research/v40-p0-symbol-locations.json`：压缩保存 v40 已核实的92条标识符、94处定义归属、11个实际模块的位置，不按缺失函数统计，支持候选输出标记 `v40LocatedNames`。
- 仅输出 `.generated/batch-restoration-candidates.json`，**不会修改 `src/`、旧版源码或恢复台账**。
- 使用 TypeScript AST 而不是简单文本查找，输出定位、证据、分组及数量。局部试运行通过 `--focus` 限定新版模块，避免每次全量扫描。

### 本地执行

在111源码工程中，先安装与 `package-lock.json` 锁定的依赖：

```sh
npm ci --ignore-scripts --no-audit --no-fund
npm run check:batch-restoration
npm run check:v40-locations
node scripts/batch-restoration-candidates.cjs \
  --old /path/to/claude-code-2.1.88-main/source/src \
  --focus chunk-tqjdehqd.js,chunk-r4g83g7p.js,chunk-w9w4r9w1.js \
  --out .generated/batch-restoration-candidates.json
```

`--all` 可以对新版全部主程序 chunk 进行候选扫描，`--v40-map` 可指定研究证据映射，`--reference` 标注使用2.1.300等其他参照版本。`--new` 可以传入其他新版源码目录，`--aliases` 指定不同的已恢复清单，`--max 200` 限制每类输出条数。旧版资料独立存放，**不复制进111仓库**。

## 验收要求与扩展次序

1. **先校准候选**：与 v36 的624组候选和 v40 的92条确权记录交叉检查；重点抽样错配、同名不同语义、压缩后合并/拆分函数与有副作用的闭包。
2. **再引入可审计批量改写**：只允许已具备新版调用链及行为证据的高置信候选进入转换；采用 AST 级变更并保留原短符号及导出接口。任何自动改写均必须逐项输出差异和回滚依据。
3. **批量定向验证**：对新增可读函数执行真正的原函数测试，记录输入、输出、异常、取消、权限分支及副作用；不能仅测试“函数名存在”。
4. **关键业务端到端验证**：按 `主查询 → 模型流 → 权限 → 工具结果 → 会话保存`、MCP、Hook、Daemon、远程控制的顺序，每条链拿到真实运行证据。
5. **最终回归**：运行 `npm test`、`npm run verify:runtime`，与原版2.1.310对照行为；网络及系统级场景无法执行时单列为待验收。

## 首轮边界

此PR新增的是**批量匹配和防错工具链**，不是已经成功自动恢复新版源码的批处理结果。旧版源码不是仓库依赖，GitHub CI运行人工构造的跨版本结构样本，并检查v40的92条归属记录对应11个真实源码模块，不宣称CI验证了真实 2.1.88 全量匹配率。

下一步需在能读取两代真实源码的同一工作环境中，对上述三个 P0 模块运行候选生成，统计高/中/歧义命中与人工抽样错误率，再决定是否启用自动可读化代码变换。
