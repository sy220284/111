# 111 全页面视觉与交互收敛：跨路由统一修订（2026-11-21）

## 范围

沿用已合并的 PR #26 桌面式侧栏、典雅白和 29 个注册路由。基于 Android 35 的 360/393/411dp 截图、四项最新技能（finesse-ui、finesse-brief、frame-smith、finesse-term）和本仓 195 项接口契约审计，集中处理所有共享页面的基础构图、导航反馈、状态展示，以及安全与接口来源模块的实际交互。

## 本次落地

1. **所有通用业务页面**：统一 `ScreenColumn` 手机边距与宽屏内容上限 840dp，页面标题与正文导语有明确区分；`SectionIntro` 以轻量暖铜导向线建立层级，保留原生字号缩放及滚动。
2. **业务状态**：提示分为信息、成功、提醒和错误四类。普通断连提示用暖棕色语义，真实接口错误保留红色。多接口同页的相同错误合并去重，同时展示不同错误，提供回到实际请求的重新加载动作。
3. **协议→页面组件**：`ProtocolFeedback` 接收 ViewModel 已有的 `loading/errors` 和指定数据键，保留真实返回内容；生态目录（模型/服务商/技能/插件/钩子）、连接应用/MCP/协作模式和权限页复用，不展示后台字段列表。
4. **权限安全**：将配置、可用权限和保存结果的错误汇总到一处，解决截图中同一断连错误连续出现两次的情况；未提交的权限调整可一键放弃，保存仍经风险确认并调用原 `config/batchWrite`。
5. **任务首页**：按开始与继续两种实际运行状态组织主标题，连接情况可查看诊断；减少重复的断连标签。
6. **会话执行记录**：操作图标以白底加细边框区分状态，颜色只承载操作语义；“执行依据”继续使用真实返回数据与现有脱敏呈现。
7. **选择/弹层**：底部选择表单增加系统导航栏留白，动作提示区维持不少于 48dp 的目标尺寸；减弱动效偏好继续生效。

## 接口校验原则

保持 `UiProtocolMatrix` 对 195 项请求的原定归属，不按接口名称生成假按钮。只有本地真实 ViewModel、用户操作对象、审批/风险确认和现有刷新链路齐备时才展示可操作入口。

| 用户场景 | 数据来源 | 交互反馈 | 后续动作 |
| --- | --- | --- | --- |
| 模型、技能与插件目录 | `vm.refresh` → `vm.data` | `ProtocolFeedback` 汇总加载/错误 | 原有目录重新加载 |
| 连接应用与 MCP | `app/list`、`app/installed`、`mcpServerStatus/list` | 明确连接结果及重试 | 原有授权和服务工具 |
| 权限与安全 | `config/read`、`configRequirements/read`、`permissionProfile/list` | 多请求去重、原始策略保留于状态 | 风险确认后 `config/batchWrite` |
| 通用页面 | 各页面现有 `Page.rpc` | 区分无数据、待加载和未连接 | 重新加载/连接运行核心 |
| 执行记录 | `vm.timeline` 与事件证据 | 白底卡片+状态图标/文字 | 可选择查看对应执行依据 |

## 验收方式

代码构建、Kotlin 单测、Android Lint、29 路由 UI 导航及模拟器截图由仓库现有 `check-android-ui.yml` 执行。每次修改后以对应分支最新提交的 CI 结果和截图产物为验收依据；离线 UI 数据用于检查形状与状态，不冒充运行核心联调。
